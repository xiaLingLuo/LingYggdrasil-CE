# 安全说明

本页说明泠 Yggdrasil 的安全机制、已知限制与运维注意事项。

> 部署前的加固清单见文末[安全部署清单](#安全部署清单)。

## 密码与加密

- 用户密码使用 **Argon2id** 算法哈希存储，永不保存明文。
- 提供 1–6 级加密等级（电磁 / 能量 / 结构 / 信息 / 引力 / 宇宙），等级越高哈希越强、计算开销越大。
- 管理员与安装向导使用更强的密码策略（至少 12 位，含大小写字母、数字与 `@$!%*?&` 之一）；普通用户默认至少 6 位，仅允许字母、数字与 `@$!%*?&`。
- 登录失败有**账户 / IP 维度**的锁定与限流。
- `sql.yml` 中的数据库/邮件密码与服务端密钥材料以加密形式保存，主密钥为运行目录的 `.lingkey`（首次自动生成，权限尽量收紧）。
- **世界树密钥**保存在 `profile_credentials`（密文 + SHA-256 摘要 + 密钥版本），旧 `player_profiles.yggdrasil_token` 仅作兼容回退。
- 秘密存储契约 `secret_store` 使用 AES-256-GCM（密文/摘要/密钥版本/AAD），迁移工具用其迁移旧 `ENC:` 秘密。

## Yggdrasil 签名

- 支持 **Ed448**（现代）、**RSA-SHA512**、**RSA-SHA1**（兼容）三种签名模式。
- 每个角色拥有独立的世界树密钥（`profile_credentials` 加密存储；登录校验优先新表，旧 token 仅兼容回退）。
- 纹理属性经签名后下发给客户端，客户端可校验其真实性。

> 切换签名模式或重新生成密钥后，客户端需要重新登录。

## 会话与 Cookie

- 用户端、管理端、API 使用**相互独立**的会话 Cookie（`LING_USER_SESSION` / `LING_ADMIN_SESSION` / `LING_API_SESSION`），避免互相登出或串号。
- 会话 Cookie 设置为 `HttpOnly`、`Secure`、`SameSite=Strict`。
- 管理会话有独立的空闲超时，并绑定客户端指纹（`validateClientFingerprint`），指纹变化会强制失效。

## 请求防护

- **CSRF**：所有写操作（POST/PUT/DELETE）校验 CSRF Token。
- **安全响应头**：所有响应包含 `Content-Security-Policy`、`X-Content-Type-Options: nosniff`、`X-Frame-Options: DENY`、`Referrer-Policy`、`Strict-Transport-Security`、`Permissions-Policy`、`Cache-Control` 等。
- **CSP**：默认 `script-src 'self' 'nonce-<随机>'`，页面内联脚本均带每请求随机 nonce；脚本仅允许同源加载。
- **速率限制**：登录、注册、纹理上传、纹理操作、日志下载等关键操作均有频率限制。
- **SQL 注入**：所有数据库访问均使用参数化查询。
- **路径穿越**：文件访问经过校验；图标名仅允许安全字符。
- **上传校验**：纹理上传校验类型、大小、PNG 尺寸/像素/分块与并发。
- **错误页**：统一的错误页处理器会对 API 路径返回 JSON、对页面路径返回 HTML。
- **反向代理兼容**：`aggregate` 模式下用户端的 `/api/yggdrasil` 为透明反向代理，完全绕过用户端自身的会话/CSRF/邮箱/限流校验，以保持与独立 Yggdrasil 服务完全一致的行为。

## 账户保护

- **邮箱验证**：可选开启，注册/改邮箱需验证码。
- **邮箱域名控制**：白名单/黑名单模式，精确控制可注册的邮箱域名。
- **同 IP 注册限制**：限制同一 IP 可注册的账号数量。
- **名称黑名单**：用户名、角色名、皮肤/披风名可配置黑名单，支持通配符。
- **封禁**：可将用户移入封禁组；被封禁用户无法通过用户端与 Yggdrasil 认证（包括已登录会话）。

## Root 完整性保护

- Root 管理员记录独立存放在 `root_info` 表。
- 程序在每次管理端请求时校验 `root_info` 是否恰好包含一条记录；若不满足，将锁定 35599 端口的全部功能并提示：

  > 数据库核心遭到篡改！为确保安全，目前已关闭35599端口的任何功能！请立即检查系统安全！

  这用于防止有人直接篡改数据库绕过 Root 校验。

## 权限与审计

- 管理端功能受权限组控制，Root 拥有全部权限。
- 高危权限在界面中明确标注。
- 管理员对用户、材质、角色、管理员、邮件配置等敏感操作写入 `audit_events`（actor/action/target/result/reason/correlationId/occurredAt），管理端 `GET /admin/api/audit` 可查询。
- 系统设置按组提交 + revision 乐观锁（409），每次成功提交写审计并生成配置快照；旧 `system_settings` 迁移到 `legacy` 组。

## 插件安全边界

| 插件类型 | 可访问范围 | 信任级别 |
|---|---|---|
| SPI（`plugins/spi/`） | 仅 JDK 与 `im.xz.cn.plugin.spi`；storage/scheduler/logger 受控 | 推荐；类加载隔离但**不是沙箱** |
| 旧 API 桥接（`plugins/legacy/`） | 桥接上下文暴露 DB/Config/数据目录；菜单/路由不支持 | 完全可信代码 |
| 传统 `plugin.yml`（`plugins/`） | 旧完整 API（菜单/路由/用户端/世界树） | 完全可信代码 |

SPI 插件虽隔离类加载，但仍运行在同一 JVM；只安装可信插件。旧 `plugin.api` 桥接将在 2.11.0 移除。

## 已知限制与注意事项

以下为已知的、需要运维者了解的事项：

1. **客户端 IP 依赖代理头**
   程序通过 `X-Forwarded-For` / `X-Real-IP` 识别客户端 IP（用于日志、限流、同 IP 注册限制）。若服务直接暴露公网，客户端可伪造该头。**务必**通过反向代理访问，并由代理覆盖这些头。

2. **CSP 允许内联样式**
   `style-src` 保留了 `'unsafe-inline'`（因页面大量使用内联样式与样式属性）。脚本已收紧为 nonce，但样式注入不在防护范围内。

3. **外部语言包的脚本上下文**
   语言包的值会被嵌入页面的 `<script>` 中（用于前端 i18n）。外部语言包文件由管理员控制，请确保 `i18n/` 目录与语言包内容可信、不可被非授权者写入。

4. **配置文件加密密钥**
   `.lingkey` 是 `sql.yml` 密码的加密密钥。丢失后无法解密已有密码，需要重新填写；泄露则可被用于解密。请限制运行目录权限并做好备份。

5. **外网域名配置错误的影响**
   「项目外网域名」配置错误会导致外置登录失败、皮肤不显示等问题；请以用户端 / 管理端展示的「当前生效 URL」为准核对。

6. **图标/静态资源目录权限**
   运行目录（含 `icons/`、`i18n/`、纹理目录）应设置为仅程序运行账户可写，避免被替换为恶意内容。

7. **管理端与安装端暴露面**
   管理端（35599）与安装端（35598）不应直接暴露公网。请使用反向代理 IP 白名单或仅通过内网/隧道访问。

8. **首页模板与邮件模板的 HTML 注入**
   首页 HTML 模板（`i18n/user/index-page/*.html`）与邮件模板支持原始 HTML。首页模板可由运行目录下的同名文件覆盖，请仅使用可信内容，并限制运行目录的写入权限。

## 设计使然的安全边界

以下事项为有意设计，安全责任在于部署者/管理员，程序不做强制限制：

1. **安装阶段不做访问保护**
   安装向导在**未安装状态**下监听 `0.0.0.0:35598`，任意可连通的客户端均可直接访问并完成安装；**不使用安装令牌**。安装阶段的安全（如仅临时开启端口、置于内网、反向代理限制来源）由安装者自行负责。安装完成后程序会写入 `.INSTALLED`、停止安装服务，安装端口随之关闭；其后 `/admin` 才是唯一入口。

2. **安全设置由 Root 全权负责**
   管理后台「安全设置」中的 CORS 白名单、安全响应头、频率设置、PNG 并发、角色名长度范围等均可由 Root 修改，且**不设硬性上限**。这些参数配置不当可能导致全站异常或防护失效，属管理员应自行评估的风险；程序仅做基础格式校验（如 CSP 必须含 `{nonce}`、CORS 来源格式、频率映射为正整数）并在界面给出红色警告，不会代替管理员决策。

3. **API 模式与反向代理的信任边界**
   `aggregate` 模式下 `/api/yggdrasil` 仅转发到本机 API 端口，上游地址固定为 `127.0.0.1`，不接受外部目标。该路由点的鉴权、限流由世界树服务自身负责。

4. **配置生效时机**
   安全响应头在每次请求时读取配置，保存后立即生效（配置错误可能当场影响页面）；CORS 白名单在服务启动时加载，修改后需**重启**方可生效。

## 安全部署清单

- [ ] 使用 HTTPS（反向代理终止 TLS）。
- [ ] 管理端（35599）限制来源 IP。
- [ ] 反向代理覆盖 `X-Forwarded-For` / `X-Real-IP`。
- [ ] 运行目录权限收紧，妥善保管 `.lingkey` 并备份。
- [ ] 定期备份数据库与纹理。
- [ ] 定期审查管理员账户与权限组。
- [ ] 及时升级到最新版本。
